シンプルな起動管理から始める

最初から高機能な統合運用システムにせず、PC上に1つのLaunch Serverを置き、 起動対象をLaunch Targetとして一覧管理します。目的は、ライブや制作中に 「何が動いているか」「どのポートか」「どう止めるか」を迷わないことです。

結論

構成を軽く保つため、Launch Managerはまず小さな親プロセスとして作ります。

最初の形

PC上に1つのLaunch Serverを起動し、`launch/targets.json` に書かれたTargetとSetを GUIから起動、停止、再起動、監視します。UIは正本を持たず、Launch Serverへ操作要求を送ります。

役割分担

曲用映像サーバーとLaunch Serverを混ぜないことが一番大事です。

Launch Server

PC上で動く起動管理の本体。起動、停止、PID、port、ログ、リソースの正本を持ちます。

Launch Manager UI

PCブラウザや将来のスマホから使う操作画面。命令を送るだけで、状態の正本は持ちません。

Launch Target

起動対象。曲用映像、fixture player、song-pack server、保存APIなどを同じ形で扱います。

Launch Set

複数Targetをまとめた起動セット。Profileより軽い概念として扱います。

MVP範囲

使われる道具にするため、最初は削ります。

最初にやる

  • PC上に1つのLaunch Server
  • `launch/targets.json`
  • Targetの起動、停止、再起動
  • Setの起動、停止
  • PID、port、URL、CPU、memory、ログ末尾の表示
  • 固定port衝突時はエラー表示

後回しにする

  • 複数Launch Serverの調停
  • attached / delegated mode
  • 自動port再割当
  • CPU/memory履歴グラフ
  • WebSocket/SSE
  • LAN公開、スマホ専用UI
  • 任意コマンド入力GUI

起動と停止

GUIタブを閉じることと、起動中プロセスを止めることは分けます。

起動の流れ

Launch Serverを起動PC上で1つだけ動かします。
UIを開くPCブラウザ、将来はスマホから同じServerへアクセスします。
TargetまたはSetを選ぶ起動対象はtargets.jsonに書かれたものだけです。
検証して起動port衝突、cwd、ログ場所を確認してからspawnします。
状態を表示health、PID、URL、ログ、resourceをUIに出します。

停止の考え方

操作挙動
個別停止対象Targetだけ停止します。
Set停止Setに含まれるTargetを停止します。
全停止Launch Serverが管理するTargetを全部停止します。
GUIタブを閉じる何も止めません。
Launch Server終了MVPでは管理中Targetを停止してから終了します。

状態と監視

細かい概念を増やしすぎず、UIでは5状態に絞ります。

stopped

停止中。基本監視しません。

starting

起動処理中。1秒ごとにhealth確認します。

running

起動中。5秒ごとにhealth/resource確認します。

stopping

停止処理中。停止完了を待ちます。

error

起動失敗、異常終了、health失敗です。

UI更新

`/api/status` を2秒ごとにポーリングします。

ログ

stdout/stderrをファイル保存し、GUIには末尾だけ表示します。

リソース

PID、CPU%、Memory MB、起動時刻、exit codeを表示します。

targets.json

RecipeとProfileを分けすぎず、最初はtargetsとsetsを1ファイルにまとめます。

{
  "targets": [
    {
      "id": "fixture-player",
      "label": "Fixture player",
      "kind": "web-app",
      "cwd": ".",
      "command": "npm",
      "args": ["run", "dev:player", "--", "--port", "5173"],
      "ports": [5173],
      "urls": {
        "open": "http://127.0.0.1:5173/"
      },
      "health": {
        "url": "http://127.0.0.1:5173/",
        "intervalMs": 5000
      }
    }
  ],
  "sets": [
    {
      "id": "basic-fixture",
      "label": "Basic fixture",
      "targets": ["fixture-player", "song-pack-server"]
    }
  ]
}

GUI

ライブ用途では、賢さより事故らなさを優先します。

画面に置くもの

  • Launch Set選択
  • Set起動、Set停止、全停止
  • Targetカード一覧
  • 起動、停止、再起動、開く
  • 状態、PID、port、URL、CPU、memory
  • stdout/stderrの直近ログ

常に見せたい注意

このタブを閉じても起動中のTargetは止まりません。停止するには各Targetの停止、Set停止、または全停止を使ってください。

安全策

スマホ操作やLAN公開は便利ですが、MVPでは入れません。

項目MVP方針
bind`127.0.0.1` のみ。
POST APIsame-originだけ許可。
起動対象targets.jsonに書かれたTargetだけ。
cwdリポジトリ内または明示許可ディレクトリ内。
GUI任意コマンド入力欄を作らない。
停止対象Launch Serverが起動したmanaged Targetだけ。

実装準備

次プロセスでは、既存dev-managerを互換入口として残しながら中身を分けます。

scripts/launch-manager/
  config.mjs       targets.json読み込みと検証
  supervisor.mjs   spawn/stop/restart/process状態
  ports.mjs        port衝突確認
  logs.mjs         stdout/stderr保存と末尾取得
  metrics.mjs      PID/CPU/memoryの簡易取得
  server.mjs       HTTP APIとHTML UI

launch/
  targets.json     初期TargetとSet
