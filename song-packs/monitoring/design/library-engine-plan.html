前提

今回の「モニタリング」は、最終的にCanvas2Dだけで、暗いドア手前から明るい居住空間を覗く表現へ刷新した。 ただし、生活空間、手書きメモ、覗き穴マスク、ポップな侵食記号をすべて手描き関数で持つと、 曲固有adapterが低レベルな描画処理で膨らみやすい。

そのため、今後同じ種類の要求が複数曲で出るなら、system本体へ固定依存として入れるより、 「曲側が任意に選べるrender layer / runtime recipe」として整理するのが全体方針に合う。

system側の集約資料は docs/library-candidates.md。 このHTMLは、モニタリング実装中に具体的に欲しくなった構成イメージを補足する曲側メモとして扱う。

非ゴール: 曲固有の部屋、色、眼、メモ文言、MV解釈をsystemへ移すことはしない。system側に求めるのは、 レイヤー作成、contentRect追従、生命周期、検証レシピなど、曲を束縛しない補助だけ。

想定した全体構成

SongAppFrametime、userGlow、safeArea/contentRect、beat/chorus解析を曲へ渡す。
Song adapter曲固有の構図、タイミング解釈、演出判断を保持する。
Optional runtime layerPixi、Rive、Rough.jsなどを曲が必要に応じて所有する。
visualHost layerCanvas2D以外のcanvasやDOMを、補助レイヤーとして生成する。
Player shell再生、入力、保存、UI、contentRectを提供する。
SongApp.render(frame)
  - frame.time is the master clock
  - beat/chorus are converted into song-local intensity values
  - contentRect decides where the song may draw
  - optional runtime layers render inside the same content bounds
  - song-specific interpretation stays in the song pack

候補別の使いどころ

Rough.js
手描き線 Canvas/SVG補助 軽量候補

手書きメモ、ハート、揺れる線、家具や小物の輪郭を「人間が描いた感じ」に寄せる候補。 今回の生活空間と相性がいちばん良い。

今回使わなかった理由は、曲1本のために依存を増やさず、Canvas2Dで十分確認できたため。 複数曲で手描き表現が続くなら、最初に検討したい。

PixiJS
レイヤー管理 mask/filter sprite

覗き穴マスク、ぼかし、ノイズ、blend、sprite、post effectをまとめて扱う候補。 Canvas2Dの手続き的な描画が多層化したら、保守性はPixi側が有利。

今回使わなかった理由は、単曲の居住空間には重く、dependencyとbundleを増やすほどではなかったため。 ただし visualHost canvasContext none があるので、将来の検証はしやすい。

Rive
表情 state machine 制作フロー必要

監視主体の眼、笑顔、メモ、キャラクター的な共感アピールを状態付きアニメとして持つ候補。 userGlowやchorusをRive inputへつなぐ形を想定していた。

今回使わなかった理由は、.riv アセット制作と管理フローが必要で、 現在の曲パックより運用が大きくなるため。

GSAP
easing 補間 主時計にしない

家具、小物、覗き穴反射などの補間を読みやすく書く候補。 ただし曲同期では frame.time が主時計なので、GSAP timelineを自走させる構成は避けたい。

使うなら、master clockを置き換えず、easing関数やseek可能な補間helperとして限定する想定。

採用判断の目安

状況 候補 判断
手描きメモ、ゆるい線、生活小物が複数曲で必要 Rough.js 共通helper化の価値あり。Canvas2Dを置き換えず、描画関数として足す。
mask、filter、sprite、blendが曲ごとに増える PixiJS optional render layer recipeとして検証。system本体の必須依存にはしない。
表情・目・キャラクターが状態機械を持つ Rive asset制作フロー、validate対象、bundle戦略を先に決める。
単純な揺れや余韻だけを読みやすくしたい GSAPまたは小さな自前easing helper 曲の主時計から独立させない。まず小さなhelperで足りるか見る。

system側にあると助かる形

  • 任意runtime recipe: `docs/recipes/pixi-song-layer.md` のような、曲側が選ぶ実装例。
  • layer lifecycle helper: create、resize、render、dispose、contentRect追従の型だけを揃える。
  • clock discipline: 外部runtimeも frame.time でseek/renderし、独立tickerを主にしない指針。
  • asset validation: `.riv`、sprite、外部参照を入れる場合も、歌詞本文や画像データを混ぜない検証方針。
  • dependency gate: bundle size、license、browser support、fallbackを採用前に確認するチェックリスト。
