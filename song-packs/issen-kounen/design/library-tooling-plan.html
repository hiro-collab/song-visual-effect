一千光年 ライブラリ導入構成メモ

一千光年担当が制作中に「既存ライブラリやツールを入れるならこう置きたい」と感じた構成案です。 曲固有の演出判断は song-pack 側に残し、system 側は optional helper、検証、参照管理だけを持つ前提で整理しています。

Owner: 一千光年担当 Audience: system 実装担当 No lyrics text stored No image/frame data stored

基本方針

曲側が決めること

MVや歌詞から何を抽象化するか、どの色や動きを主役にするか、セクションごとの演出判断。

system側が持つこと

safe area、DPR、文字fit、参照URL検証、preview snapshotなど、曲を縛らない補助。

避けること

歌詞本文・記事本文・MV画像の保存、公式絵の複製、独立clockで音楽時刻とズレるtimeline。

想定レイヤ構成

song-pack / adapter

曲固有の点列、色、強弱、セクション解釈を作る。例: 黄緑の筆線の中心線、声の花びら配置、歩幅。

down: small data / draw intent
system/kit optional helpers

contentRect、fitTextToRect、将来の drawBrushStroke、 valueAtTime など。曲側から呼ばれた時だけ使う。

down: verification / authoring loop
scripts / dev tooling

song:validate、将来の preview:snapshot。 URL参照の安全性、console error、safeArea衝突、指定時刻のスクショ確認を担当する。

候補ライブラリと置き場所

領域 候補 使いたくなった理由 今回は使わなかった理由 入れるなら 優先度
手描き・筆線 perfect-freehand, paper.js, rough.js MV由来の黄緑の筆線を、点列から自然な太さ・丸み・かすれにしたい。 曲branchで依存を増やすと bundle/security/表現方針の評価が重い。今回はCanvas2Dで足りた。 system側で optional stroke helper として評価。曲側は点列、色、太さ、roughnessだけ渡す。 P2 evaluate
時間補間 GSAP, anime.js 手作りの mix / smoothstep が増え、曲ごとに同じ補間を書くことになる。 独立clockのtimelineは previewTime、seek、停止再開で音楽時刻とズレやすい。 ライブラリtimelineではなく、frame.time 駆動の easing / interpolation helper をsystemに置く。 P2 evaluate
プレビュー検証 Playwright / browser automation 指定時刻スクショ、console error、safeArea衝突は毎回手確認になりがち。 現状はブラウザ確認で十分だったが、担当間レビューでは再現性が弱い。 npm run preview:snapshot -- --song issen-kounen --time 56.21 で画像とJSONを出す。 P1 next
2D scene/layout PixiJS, Konva, p5.js レイヤ、図形、テキスト、イベントを抽象化できる。 一千光年は軽量Canvas2Dで十分。大きなscene engineは曲の自由度を逆に縛る可能性がある。 すぐ導入しない。まず visualHost layer と contentRect/textFit helper を育てる。 Hold
3D・ゲームエンジン Three.js, Phaser, Matter.js 3D空間や物理ルールが主役の曲なら有効。Three.jsは既にsystemで利用可能。 今回の主役は筆線と窓辺で、物理や3D sceneは過剰。 採用基準をdocs化。曲の主役構造が3D/物理でない限り標準化しない。 Not for this song

APIイメージ

筆線 helper

const points = samplePaintPath(frame.time, chorus);
drawBrushStroke(ctx, points, {
  rect: scene.contentRect,
  color: "#8cff47",
  width: valueAtTime(frame.time, cues),
  roughness: beat.pulse
});

曲側は中心線と意味だけを作る。線の丸み、かすれ、DPR対応、clipはsystem helperが担当する。

時刻駆動 helper

const openness = cueValueAt(frame.time, [
  { start: 56.21, end: 79.95, from: 0.2, to: 1, ease: "outCubic" }
]);
const y = mix(baseY, chorusY, openness);

内部clockは持たず、常に frame.time を入力にする。seekやpreviewTimeに強い。

確認方法

  • npm run song:validate -- --id issen-kounen で参照URLメタデータだけが保存されていることを確認する。
  • npm run build で、optional helper が使われない曲にも影響しないことを確認する。
  • 将来 preview:snapshot が入ったら、56.21s などサビ頭でスクショ、console error、safeArea衝突を確認する。
